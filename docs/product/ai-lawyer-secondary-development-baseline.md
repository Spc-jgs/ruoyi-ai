# AI 律师系统二开基调与模块边界

> 版本：v1.0
> 基线：RuoYi-AI tag 3.0.0
> 日期：2026-05-08
> 用途：明确 AI 律师系统的产品基调、角色端划分、业务闭环、MVP 范围和模块边界

---

## 1. 产品基调

### 1.1 不是单纯 AI 问答

AI 律师系统 = **AI 法律咨询入口** + **律师服务撮合平台** + **合同模板交易平台** + **律所管理工具** + **服务商数据平台** + **平台运营后台**

### 1.2 核心商业逻辑

```
C 端用户免费 AI 咨询（引流）
  → 咨询转律师委托（变现）
  → 合同模板下载（增值）
  → 律师 AI 工具赋能（留存律师）
  → 律所抽佣 + 服务商数据分润（平台收益）
```

### 1.3 当前原则

- 先复用 RuoYi-AI 的 AI 对话、知识库、权限、菜单、文件上传、SSE 能力
- 新业务模块优先新增，不直接污染 ruoyi-chat 核心链路
- AI 律师业务模块独立拆分
- 初期不做复杂支付、佣金、IM、分账
- 后续再考虑腾讯 IM、订单、合同模板付费、律所抽佣

## 3. 主业务闭环

### 3.1 C 端 AI 法律咨询闭环

| 项目 | 内容 |
|------|------|
| **参与角色** | C 端用户、AI 系统 |
| **主流程** | 用户打开 App → 选择 AI 咨询 → 输入法律问题 → AI 基于法律知识库回答 → 回复含免责声明 → 用户追问或结束 |
| **产生数据** | `chat_session`、`chat_message`（复用 RuoYi-AI） |
| **是否适合 MVP** | **是**，核心引流闭环 |
| **风险** | AI 回答准确性风险、无 Rerank 影响检索质量、需免责声明 |

### 3.2 C 端找律师闭环

| 项目 | 内容 |
|------|------|
| **参与角色** | C 端用户、律师 |
| **主流程** | AI 咨询后点击"找律师" → 浏览律师列表（按专业/地区/评分） → 查看律师详情 → 发起咨询意向 → 律师接受 → 建立服务关系 |
| **产生数据** | `consult_intention`（咨询意向）、`lawyer_service_order`（服务订单） |
| **是否适合 MVP** | **简化做**，一期只做意向提交，不做在线支付 |
| **风险** | 律师响应时效、服务定价策略未定、是否需要 IM |

### 3.3 律师入驻/审核闭环

| 项目 | 内容 |
|------|------|
| **参与角色** | 律师、平台审核员 |
| **主流程** | 律师注册 → 填写执业信息 → 上传执业证 → 平台审核（可复用 Warm-Flow） → 审核通过/驳回 → 律师身份激活 |
| **产生数据** | `lawyer_info`（律师信息）、`lawyer_audit_record`（审核记录） |
| **是否适合 MVP** | **是**，律师入驻是业务前提 |
| **风险** | 执业证 OCR 识别、是否对接司法部数据库、审核 SLA |

### 3.4 合同模板上传/审核/下载闭环

| 项目 | 内容 |
|------|------|
| **参与角色** | 律师（上传方）、平台审核员、C 端用户（下载方） |
| **主流程** | 律师上传合同模板 → 填写分类/标签/定价 → 平台审核 → 审核通过上架 → C 端浏览/搜索 → 下载（免费或付费） → 律师获收益 |
| **产生数据** | `contract_template`（合同模板）、`contract_template_order`（下载记录） |
| **是否适合 MVP** | **简化做**，一期只做免费模板上传/审核/下载，不做付费 |
| **风险** | 模板质量审核、版权归属、是否需要模板预览 |

### 3.5 律所管理/抽佣闭环

| 项目 | 内容 |
|------|------|
| **参与角色** | 律所管理员、律师 |
| **主流程** | 律所注册 → 邀请/审核律师加入 → 律师服务产生收益 → 按配置比例抽佣 → 数据看板查看 |
| **产生数据** | `law_firm_info`（律所信息）、`law_firm_lawyer`（律所-律师关系）、`commission_record`（佣金记录） |
| **是否适合 MVP** | **不做**，一期只预留数据结构 |
| **风险** | 佣金计算复杂、分账对接、律所-律师关系变更 |

### 3.6 服务商数据查看闭环

| 项目 | 内容 |
|------|------|
| **参与角色** | 服务商 |
| **主流程** | 服务商登录 → 查看管辖范围内的数据（用户量/咨询量/律师活跃度等） |
| **产生数据** | 依赖数据权限隔离 |
| **是否适合 MVP** | **不做**，一期无此需求 |
| **风险** | 数据权限边界不清晰 |

### 3.7 平台管理闭环

| 项目 | 内容 |
|------|------|
| **参与角色** | 管理员/运营/审核/客服 |
| **主流程** | 登录管理端 → 账号管理/律师审核/内容审核/数据运营/系统配置 |
| **产生数据** | 复用 RuoYi-AI 管理端 + 新增业务审核记录 |
| **是否适合 MVP** | **是**，复用 RuoYi-AI 管理端 + 新增业务菜单 |
| **风险** | 菜单权限设计需提前规划 |

## 4. MVP 建议

### 一期必须做

| 功能 | 理由 |
|------|------|
| C 端 AI 法律咨询 | 核心引流闭环，验证 RuoYi-AI 对话链路可用性 |
| 律师入驻/审核 | 业务前提，验证工作流能力 |
| 律师信息管理 | 律师列表/详情展示的数据基础 |
| 合同模板上传/审核/免费下载 | 验证文件上传/OSS/RAG 全链路 |
| 管理端基础菜单 | 复用 RuoYi-AI，新增律师/合同管理菜单 |

### 一期简化做

| 功能 | 简化方案 | 理由 |
|------|---------|------|
| C 端找律师 | 只做律师列表 + 咨询意向提交，不做在线支付 | 支付复杂度高，先验证撮合链路 |
| 合同模板付费 | 一期全部免费 | 支付/分账体系未设计 |
| 律所管理 | 一期只做律所信息 CRUD，不做抽佣 | 抽佣逻辑复杂，后续再设计 |

### 一期不建议做

| 功能 | 理由 |
|------|------|
| 在线支付/分账 | 需要支付牌照、对账、退款，复杂度极高 |
| IM 即时通讯 | 腾讯 IM 集成工作量大，一期用留言/意向替代 |
| 服务商数据平台 | 需求不明确，数据权限边界不清 |
| 律师 AI Agent 深度定制 | 需要先验证基础 AI 对话能力 |

### 后续版本再做

| 版本 | 功能 |
|------|------|
| M4 | 合同模板付费下载、律师在线咨询支付 |
| M5 | 律所抽佣、服务商数据平台、腾讯 IM |
| M6 | 律师 AI Agent 深度定制、法律知识图谱、模拟法庭 |

### 6.5 `ruoyi-service-provider`（后续版本）

| 项目 | 内容 |
|------|------|
| **职责** | 服务商管理、数据权限、数据看板 |

## 7. 暂时不能动的核心模块

| 模块/类 | 不能动的原因 | 什么时候可以动 |
|---------|-------------|--------------|
| `ruoyi-common-*`（全部 24 个） | 公共底座，修改影响全局 | 永远不要动，除非有充分理由 |
| `ruoyi-system` 的 `sys_*` 基础表 | RuoYi 基础功能（登录/权限/菜单）依赖 | 永远不要动 |
| `ChatServiceFacade` | AI 对话核心入口，603 行，拆分风险极高 | M3 阶段评估拆分方案 |
| `ChatServiceFactory` | 模型路由核心，所有 Provider 依赖 | 永远不需要改，新增 Provider 自动发现 |
| `VectorStoreStrategyFactory` | 向量库策略路由，3 种实现依赖 | 永远不需要改，策略模式可扩展 |
| `SseMessageUtils` / `SseEmitterManager` | SSE 推送核心，断连/漏推风险极高 | 永远不要动 |
| `ruoyi-common-tenant` 多租户插件 | 数据隔离根基，改错会越权 | 永远不要动 |
| `ruoyi-common-satoken` 认证体系 | 安全根基，改错会鉴权失败 | 永远不要动 |
| `R<T>` / `TableDataInfo<T>` | 前后端契约，改了前端全挂 | 永远不要动 |
| `BaseEntity` / `BaseMapperPlus` / `MapstructUtils` | ORM 基础设施 | 永远不要动 |
| `PersistentChatMemoryStore` | 历史消息持久化 | M3 阶段如需扩展可轻微改造 |
